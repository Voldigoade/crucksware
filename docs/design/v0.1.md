# v0.1.0 Design

This document defines the first usable Crucksware milestone. The filesystem comparison
core and text and JSON report writers are implemented. The command-line interface is
still in development.

## Goal and scope

Compare two extracted Linux root filesystem directories and answer what changed between
them. Produce deterministic text or versioned JSON. Inputs remain local, read-only, and
stable for the duration of a comparison.

The comparison includes regular files, directories, literal symbolic links, FIFOs,
sockets, character devices, and block devices. Special nodes are metadata-only and are
never opened. The root directory is a container and is excluded from change rows, though
its metadata is checked for mutation.

The milestone does not extract firmware, read firmware containers, detect renames,
compare ownership, timestamps, ACLs, extended attributes, capabilities, hard-link
topology, or sparse allocation. It does not interpret ELF files, scripts, configuration,
startup services, or certificates. It does not emulate firmware, scan for
vulnerabilities, or provide a GUI. There is no stable Rust library API promise.

## Command line

```text
crucksware compare [OPTIONS] OLD NEW
crucksware --help
crucksware --version

Options:
  --format <text|json>       default: text
  --max-entries <N>          default: 1000000
  --max-depth <N>            default: 256
  --max-path-bytes <N>       default: 67108864
  --max-bytes-read <N>       default: 1099511627776
```

Limit values are positive decimal integers. They must fit in `u64`; depth must also fit
in `usize`. Zero, negative, overflowing, and malformed values are usage errors. Use `--`
when a root path begins with a hyphen. Root paths use the operating system's native
representation, including non-UTF-8 paths on Linux.

Exit status 0 means the comparison completed with no changes. Exit status 1 means it
completed with changes. Exit status 2 means usage, platform, input, resource, mutation,
or output failure. Help and version exit 0. Successful report data goes to stdout;
diagnostics go to stderr. No report is emitted before comparison and final validation
complete. A failed write or flush exits 2, though bytes already accepted by the output
destination cannot be recalled.

There is no default command, configuration file, environment override, output-file
option, color, progress display, terminal-width adaptation, or hidden exclusion.

## Tree traversal and paths

Resolve each supplied root to an existing directory once. Explicit root symlinks are
accepted. Roots may be equal or overlap. Do not canonicalize discovered child paths or
link targets.

Walk with link metadata and read link targets literally. Descend only into actual
directories. Broken, absolute, cyclic, and escaping discovered links are opaque entries;
their targets are never traversed. Include hidden entries and empty directories. Fail on
unreadable entries and directory iteration errors rather than silently omitting data.
Filesystem boundaries below a root are errors. Same-device bind mounts are not reliably
detected and are outside the input contract.

Internally, each relative path is nonempty Unix bytes separated by `/`. Reject NUL,
absolute paths, empty components, `.` and `..`. Preserve case and bytes without Unicode
normalization or lossy conversion. Sort by unsigned raw path bytes, independent of
directory enumeration order and locale.

The output encoding `unix-percent-v1` leaves ASCII letters, digits, `/`, `.`, `_`, and
`-` literal. Every other byte becomes `%HH` using uppercase hexadecimal; `%` becomes
`%25`. For example, `a b` becomes `a%20b`, newline becomes `%0A`, and byte FF becomes
`%FF`. Apply the same encoding to symlink targets and diagnostic paths. Sort raw paths,
not their display strings.

## Entries and change classification

Kinds are `file`, `directory`, `symlink`, `fifo`, `socket`, `char_device`, and
`block_device`. Unknown kinds fail explicitly.

Compare mode bits masked by `0o7777` for all kinds except symlinks. Compare raw Linux
device IDs for character and block devices. File and directory sizes, inode numbers,
owner IDs, and timestamps are not semantic differences.

Produce at most one row for each path in the sorted union of both trees. The first
matching condition determines its category:

| Condition | Category | Changed fields |
| --- | --- | --- |
| Present only in NEW | `ADDED` | none |
| Present only in OLD | `REMOVED` | none |
| Entry kinds differ | `TYPE_CHANGED` | `type` |
| Same-kind file size or bytes differ | `MODIFIED` | `content`, and `mode` if changed |
| Same-kind link target bytes differ | `MODIFIED` | `symlink_target` |
| Only compared metadata differs | `METADATA_CHANGED` | `mode` and/or `device_id` |
| No semantic difference | no row | increment `unchanged` |

Changed fields always use this order: `type`, `content`, `symlink_target`, `mode`,
`device_id`. A type change lists only `type`; before and after entries retain their full
attributes. Content and mode changes on one file form a single `MODIFIED` row with both
fields.

Added or removed directories do not suppress descendant rows. Replacing a directory with
a file reports the parent type change and removal of old descendants. Equal content at
different paths does not imply a rename. Hard-linked paths are compared independently.

## Content and mutation checks

Use presence, kind, size, and empty-file checks before reading file content. A size
mismatch establishes a content change. Equal-size nonempty regular files are compared
byte-for-byte with two 64 KiB buffers. Do not use timestamps or size alone to claim
content equality. Stop at the first differing byte. Handle short reads and interrupted
reads correctly, preserve other read errors, and account for actual bytes read from both
files against the shared limit. Do not read special nodes.

Capture internal stamps for device, inode, mode, length, modification time, and change
time. Stamps are not report data. Check directory stamps around enumeration, file path
and handle stamps around content reads, then revalidate both roots and all recorded
entries before returning a result. Unexpected EOF, disappearance, replacement, duplicate
discovery, and stamp mismatch are errors. Never return a partial successful comparison.

These path-based checks detect ordinary changes but do not form an atomic snapshot or
contain hostile concurrent path replacement. Input trees must remain stable and
operator-controlled. Do not use live pseudo-filesystems or mutable mount topology as
inputs.

## Resource limits and read-only behavior

The four limits are shared across OLD and NEW:

| Resource | Default | Accounting |
| --- | ---: | --- |
| Entries | 1,000,000 | Each discovered non-root entry on both sides |
| Depth | 256 | Relative path components, with a root child at depth 1 |
| Path bytes | 67,108,864 | Raw relative path and literal link target bytes |
| Content bytes read | 1,099,511,627,776 | Actual regular-file bytes read from both sides |

Use checked arithmetic and fail on a limit; never truncate or skip rows. Bound directory
name collection before sorting. Check depth before descending and byte budgets before
reads. These logical limits do not guarantee an exact memory, latency, or wall-clock
bound. Metadata system calls are not included in the content-byte limit.

Open input files read-only. Never create, truncate, chmod, delete, rename, extract,
execute, or repair inside the compared trees. Filesystem reads may update access times.
Use a read-only mount when preserving access times matters.

## Reports

Text output has one row per change:

```text
CATEGORY<TAB>ENCODED_PATH<TAB>DETAILS<LF>
```

Added and removed details are `kind=KIND`. Type-change details are `type=OLD->NEW`.
Same-kind details follow changed-field order: `content`, `target=OLD->NEW`,
`mode=OLD->NEW`, and `device_id=OLD->NEW`, separated by commas. Modes use four octal
digits; device IDs use decimal. Symlink targets use `unix-percent-v1`. Do not include
roots, banners, ANSI sequences, timestamps, host data, or unbounded input strings.

End with exactly one summary line, even for an empty comparison:

```text
Summary: added=N removed=N modified=N type_changed=N metadata_changed=N unchanged=N
```

JSON schema version 1 is a pretty-printed UTF-8 object with two-space indentation and
one trailing LF. Top-level keys appear in this order: `schema_version` (integer 1),
`tool_version` (version string), `path_encoding` (`unix-percent-v1`), `summary`, and
`changes`. Summary counts are nonnegative integers ordered `added`, `removed`,
`modified`, `type_changed`, `metadata_changed`, `unchanged`.

Each change has `path`, `category`, `changed_fields`, `before`, and `after`, in that
order. Categories are the uppercase names above. Before is null only for additions;
after is null only for removals. Each entry always has `kind`, `size_bytes`, `mode`,
`symlink_target`, and `device_id`; inapplicable values are null. File sizes and device
IDs are unsigned decimal strings to retain the full `u64` range. Modes are four octal
digits, or null for symlinks. Targets use the path encoding.

The JSON report implementation freezes the schema at `docs/json/schema-1.json`. A change
to schema fields, types, values, encoding, or meaning requires a schema version
increment. Schema version and program SemVer are separate. Consumers reject unknown
schema versions and do not depend on object-key order for parsing. The byte-level output
order remains deterministic.

## Errors and architecture

Errors identify the operation, side, and safely encoded path where applicable, preserve
underlying I/O errors, and distinguish invalid paths, unsupported types/platforms,
filesystem boundaries, tree changes, resource limits, and output failures. Fail fast on
required input and output errors.

The package has an experimental Rust library and a command-line binary. Modules cover
paths, models, errors, limits, inventory, exact content comparison, classification,
report rendering, argument parsing, and process orchestration. Filesystem access uses
the standard library. Keep input backends and abstractions focused on implemented needs.
