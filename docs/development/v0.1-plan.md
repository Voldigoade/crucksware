# v0.1.0 Implementation Plan

This plan tracks the work needed for the first usable command-line milestone. Product
behavior is defined in [the v0.1.0 design](../design/v0.1.md).

## Current state

The extracted-directory comparison core is implemented: paths, models, errors, limits,
inventory, exact file comparison, revalidation, and deterministic classification.
Reporting and the command-line interface remain to be implemented. Final milestone
qualification is deferred.

## Reporting

1. **Text report.** Add a deterministic writer over a completed comparison result. Add
   exact golden fixtures for each category and changed field, raw non-UTF-8 names,
   control bytes, targets, modes, device identifiers, and empty results. Test writer
   failures. Keep output independent of terminal state and host data.

2. **JSON report.** Add schema version 1 with ordered typed output structures and freeze
   `docs/json/schema-1.json`. Check current serializer documentation, maintenance,
   license, features, and the full dependency graph before adding dependencies. Test
   complete golden output, structure and types, nullability, full-width integer strings,
   path encoding, repeatability, trailing newline, empty results, and writer errors. Do
   not add unrelated fields.

## Command-line integration

3. **CLI and process behavior.** Implement `crucksware compare [OPTIONS] OLD NEW`, help
   and version output, text and JSON formats, and the four documented resource limits.
   Validate decimal values and preserve OS-native arguments. Use exit status 0 for no
   differences, 1 for differences, and 2 for usage, platform, input, resource, mutation,
   or output errors. Keep report data on stdout and diagnostics on stderr. Do not emit a
   partial report after comparison failure. Check the current command parser
   documentation and dependency graph before adding a parser dependency. Test the real
   executable, including `--`, non-UTF-8 Linux paths, deterministic output, stream
   separation, failure cases, and unchanged source trees.

## Milestone qualification

4. **Acceptance review.** Compare the implementation with the complete design, cover all
   report and command contracts, resource boundaries, read errors, mutation checks, and
   preservation of inputs. Run the full local and hosted verification gates. Record
   platform, test, dependency, and limitation evidence. If performance measurements are
   needed, record their environment and method and report observations only. Correct
   documentation and license records. This plan does not authorize a release, tag,
   package publication, or expansion into direct firmware formats.

## Verification

Run these commands before integration:

```sh
cargo fmt --check
cargo check --locked --all-targets
cargo clippy --locked --all-targets --all-features -- -D warnings
cargo test --locked --all-features
git diff --check
cargo tree --locked
```

The primary CI target is stable Rust on Linux. No Windows support claim is made without
platform-specific implementation and verification.
